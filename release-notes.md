## [8.0.0](https://github.com/dirkwa/canboat-fork/compare/v10.0.0...v8.0.0) (2026-11-25)


###   BREAKING CHANGES

* a set-1 record of a nested PGN carries its own "list2" array in JSON, instead of "list2" being a sibling of "list". The XML schema gains RepeatingFieldSet2Parent, and the C Pgn struct and the Rust PgnInfo and DecodedField structs gain a field.
* **json:** DecodedPgn has a new public field, decoded_bits, so code that builds a DecodedPgn with a struct literal must set it. -debug and -empty JSON gain the trailing Reserved/Spare fields and "trailing". Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com> Claude-Session: https://claude.ai/code/session_017gZmLYCr5eSMaAAmZGgARg
* **decode:** leave out a value above RangeMax as out of range ([#1180](https://github.com/dirkwa/canboat-fork/issues/1180))
* **json:** each 126208 list entry with a value now has a "parameterId" key, the camelCase id of the field of the commanded PGN that the parameter names, between "parameter" and the value. The key is "parameterId" in every JSON key style.
* **decode:** a field that selects its PGN variant and has no lookup is now written as its description (a string, or {"value","name"} with -nv) instead of as a number. In the samples this is about 11,700 messages: 130822 command, 130817 deviceType, 130823 reportType, 130827 messageId, 61184 and 130816 proprietaryId, and Garmin 126720 unknownId1-4. In the Rust library such a field is a FieldValue::Lookup with its description as name, instead of a FieldValue::Integer.
* **decode:** a lookup value the lookup doesn't name and that is not one of the field's sentinels now appears as its number instead of being left out (JSON) or shown as Unknown (text). In the samples this is about 400 messages: 127501 Binary Switch Bank Status indicators of 2 (error), 129540 Range Residual Mode 2, 129038 Nav Status 13, and catch-all Industry Code 6.
* **json:** a NAME (ISO_NAME field, plain or as -nv's "value") and any integer field wider than 53 bits are now written as a JSON string of their digits instead of as a bare number: about 1,100 messages in the samples, mostly 130840's source.
* **database:** 65379 subMode, 65288 alarmPriority, 128776 speedControl and 130829 helm and subHelm are now numbers in JSON ("subMode":0) instead of hex strings ("subMode":"00 00"), and their all-ones value is left out as not available.
* **database:** these lookup values are written with their new names, in JSON and text output alike. A reader that matches on "Auto Turn" for SeaTalk command 17, or on any of the other old names for the renamed codes, needs the new name.
* **json:** JSON output now includes "list":[] / "list2":[] for a PGN with a repeating set and no records (about 6,800 messages in the samples, e.g. 129029 with 0 reference stations and B&G 130824 with no keys), where it used to leave the key out. 129029 and other PGNs with a count of 0 and trailing padding no longer give a list with one empty record ([{}] in JSON, n/a fields in text). DecodedPgn::has_repeating_set is true whenever the PGN defines the set.
* BridgeConfig names its gateway in one field, device: Option<Device>, in place of actisense, aos, ikonvert, maretron, socketcan, canalyst, canalyst_channel, usb_can_a and gateway, and of the settings that went with them (baud, ngt1_mode, socketcan_*, maretron_password, ikonvert_*, ignore_checksum, the node's address and ISO NAME, pgn_lists, learn_tx_pgns): those are Device's now. bridge::Gateway and bridge::GatewayKind are gone; bridge::Kind and bridge::Device stand in. The Supervisor type is gone too: a Device with reconnect(true) is the supervised handle.
* --kind ikonvert tcp://host connects to port 2000, the NavLink2's, instead of 6001; give the port for anything else, such as a ser2net bridge.
* BridgeConfig has a new field, ignore_checksum; a struct literal without ..Default::default() needs it.
* InputFormat has a new variant, Mxpgn; a match on it needs an arm for it.
* BridgeConfig has a new field, usb_can_a; a struct literal without ..Default::default() needs it.
* BridgeConfig has new fields. An option given for a gateway that does not have it is now an error, where it used to be ignored.
* the Rust InputFormat::Chetco variant is now InputFormat::SeaSmart.
* BridgeConfig has a new field, gateway; a struct literal without ..Default::default() needs it.
* BridgeConfig::socketcan_address is now BridgeConfig::address, and BridgeConfig gains the canalyst and canalyst_channel fields, so a BridgeConfig struct literal must name the new fields (or use ..BridgeConfig::default()). Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
* **ngt1:** `canboat::codec::ngt1::Config` has a new public field, `operating_mode`; build it with `..Default::default()`.
* **decode:** EncodeError is #[non_exhaustive] and has a new ProprietaryHeader variant; an exhaustive match on it needs a wildcard arm. PgnBuilder::build refuses a 126208 Read/Write Fields whose Manufacturer Code / Industry Code header does not match its commanded PGN.
* **node:** canboat::device::heartbeat_frame returns Result<Frame, EncodeError> instead of Frame.
* **encode:** `push(field, <integer>)` on a scaled field now means a value in the field's unit, not raw wire bits; use `Raw(n)` for those. `From<u64> for EncodeValue` is removed; use `Raw(n)` or a `Name`.
* **encode:** EncodeError::ValueOutOfRange has a new field, range, and encoding a number outside its field's range is now an error.
* JSON TIME and DURATION values are numbers of seconds instead of HH:MM:SS strings, and -nv's value is seconds instead of the wire count.
* consumers of `-si` / `--units si` output receive these fields in SI units: engine speed in Hz rather than rpm, fuel volumes in m3 and fuel rates in m3/s, and so on.
* consumers of `-si` / `--units si` output receive percentage fields as ratios, 1/100 of the previous value.
* **json:** default decoded output to camelCase ids and SI units ([#814](https://github.com/dirkwa/canboat-fork/issues/814))
* the `n2kd` and `n2kd_monitor` binaries are no longer built or installed. Use `canboat n2kd`, or run `canboat install-shims` to get an `n2kd` symlink. The `/etc/default/n2kd` and `/etc/default/n2kd_nmea` sample configs are no longer shipped.
* **rust:** derive the compiled-in schema from database/*.yaml via keel
* **rust:** move the Cargo workspace to the repo root
* **rust:** drop canboat-wire, the binary port and the wire API
* **analyzer:** give match fields a real member, not a "=275" unit string
